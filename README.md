# Тропа

Конструктор планирования путешествий на основе [Tutu MCP](https://mcp.tutu.ru/mcp).

Собираешь поездку по кирпичикам на карте — система наполняет её реальными
покупаемыми предложениями Туту. В конце «Checkout всего маршрута» пере-проверяет
каждое плечо живьём и отдаёт свежие ссылки на оплату: план не может устареть.

**У Wanderlog маршрут — картинка. У нас — корзина.**

## Запуск

```bash
npm install && npm run dev
```

Открыть http://localhost:3000. Ключи не нужны: MCP Туту работает без
авторизации.

## Переменные окружения

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `TUTU_MCP_URL` | `https://mcp.tutu.ru/mcp` | адрес MCP-сервера |
| `TROPA_CACHE_TTL_MS` | `600000` (10 мин) | TTL кэша поисков; на демо — `86400000` |
| `OPENROUTER_API_KEY` | — | ИИ-копилот; без ключа ручной режим работает полностью |
| `OPENROUTER_MODEL` | `openai/gpt-4o-mini` | любая модель OpenRouter |
| `NEXT_PUBLIC_TILES_URL` | — | тайлы карты отелей; без них карта в схематичном режиме |
| `NEXT_PUBLIC_TILES_URL_DARK` | — | тёмный стиль тайлов |
| `NEXT_PUBLIC_TILES_ATTRIBUTION` | `© MapTiler © OpenStreetMap` | подпись в углу карты |

`NEXT_PUBLIC_*` вшиваются в клиентский бандл **на этапе сборки**: менять их
в рантайме бесполезно, нужна пересборка. Шаблон — `.env.example`.

## Деплой

Docker, один контейнер:

```bash
cp .env.example .env   # заполнить ключи
docker compose up -d --build
npm run warm           # прогреть кэш демо-легендой
```

Наружу приложение не смотрит: контейнер слушает `127.0.0.1:3000`, снаружи
его публикует nginx хоста — пример блока в `deploy/nginx.conf.example`.

Две вещи, которые ломают демо, если их не учесть:

1. **Реплика ровно одна.** Кэш поисков живёт в памяти процесса. Второй
   контейнер — второй пустой кэш: прогрев не поможет, оптимизатор снова
   уйдёт на минуты.
2. **`proxy_read_timeout` в nginx — 320 с.** У `/api/optimize` и
   `/api/transfer` `maxDuration = 300`: они перебирают хабы и даты живыми
   запросами к Туту. Дефолтные 60 с рвут такой запрос на 504.

Прогрев измеримо помогает: холодный прогон легенды — 48 с, повторный — 0.1 с.

## Структура

```
src/lib/mcp.ts       вызов инструментов MCP (streamable HTTP, session-less)
src/lib/cache.ts     in-memory кэш с TTL
src/lib/search.ts    поиск плеч и отелей, нормализация офферов, checkout-ссылки
src/lib/trip.ts      модель Trip/Leg/Stay: деривация ночёвок, стыковки, мутации
src/app/api/search   POST — поиск на плечо (kind=leg) или отеля (kind=stay)
src/app/api/checkout POST — ре-валидация всего маршрута + ссылки на оплату
```

## Тесты

```bash
npx vitest run
```

Покрыты правила модели: деривация ночёвок по календарным датам в локальном
времени, инвариант стыковок, сброс офферов при мутациях, суммирование бюджета.

## API

Поиск на плечо (`mode` опционален; без него — мультитранспорт):

```bash
curl -X POST localhost:3000/api/search -H 'Content-Type: application/json' \
  -d '{"kind":"leg","origin":"Порту","destination":"Лиссабон","date":"2026-09-15"}'
```

Ре-валидация маршрута и ссылки на оплату — `POST /api/checkout` с телом
`{legs, stays}`; возвращает по каждому пункту свежую цену, diff против плана
и `checkout_url`.

## Заметки по MCP

- `search_rail` принимает `departure_date`, не `date`.
- Поезда и электрички — только Россия; на зарубежных плечах мультитранспорт
  сам предлагает автобус или самолёт.
- `create_checkout_link` принимает объект `checkout_ref` из оффера как есть.
- Ссылки `mtp-deeplink.tutu.ru` отдают 401 на curl (бот-защита) — проверять
  только в браузере.
- `get_rail_seatmap` с `view='full'` отдаёт геометрию мест (`position`,
  `size`) — схему вагона можно рисовать прямо из ответа.

## Оптимизатор маршрута

`POST /api/optimize` с телом `{legs}` — детерминированный перебор перестановок
промежуточных городов (2-opt свапы) и сдвигов старта ±1-2 дня. Ночи
«путешествуют» вместе с городом, режим пары сохраняется из плана, цены идут
через тот же кэш, что и поиски интерфейса. Скоринг — цена + время в пути
(5 ₽/мин по умолчанию, `timeWeightRubPerMin` в теле запроса). Возвращает
до 3 предложений с дельтами. На прогретом кэше отрабатывает мгновенно;
холодный прогон длинного маршрута — минуты (на демо кэш прогревается заранее).

## ИИ-копилот

`POST /api/assist` — OpenAI-совместимый chat completions через OpenRouter
(`OPENROUTER_API_KEY` в `.env.local`, модель — `OPENROUTER_MODEL`). Три роли:
черновик маршрута (инструмент `propose_trip`; черновик применяется тем же
код-путём, что и ручная сборка — автопоиск наполняет его реальными офферами),
комментарии к плану (бюджет и стыковки берутся из контекста плана, не
выдумываются) и советы по городам (в интерфейсе помечены «советы ИИ»).
Без ключа копилот честно отключается — ручной режим не затронут.
