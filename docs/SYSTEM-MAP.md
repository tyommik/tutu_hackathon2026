# Карта системы

Next.js 16 (App Router) + React 19 + zustand. Один процесс, одна реплика —
кэш поисков живёт в памяти. Зависимостей минимум — осознанно: карта, тайлы,
маркдаун и морфология написаны руками, потому что каждая библиотека на демо —
лишняя точка отказа.

## Поток данных

```
клиент (zustand-стор useTrip — оркестратор)
   │  POST /api/*
   ▼
api-роуты (единственное место общения с внешним миром)
   │
   ├─ search / checkout / optimize / transfer / rooms / seatmap
   │        │ нормализация офферов (lib/search.ts)
   │        ▼
   │     lib/mcp.ts ──── Tutu MCP (streamable HTTP, session-less JSON-RPC)
   │        │
   │     lib/cache.ts (in-memory TTL; на демо — сутки, прогрев scripts/warm.mjs)
   │
   ├─ assist / transcribe ──── OpenRouter (chat completions / ASR)
   ├─ rates ──── ЦБ РФ (XML, снапшот-фолбэк lib/ratesSnapshot.json)
   └─ geo  ──── серверный справочник координат (Natural Earth, 15k городов)
```

Клиентский цикл: мутация плана → `hydrate()` дозагружает всё недостающее
(поиск плеч → деривация ночёвок → поиск отелей → пересадки для пустых плеч
→ авторемонт стыковок) → каждый шаг пишет статус в журнал агента → когда всё
затихло и был черновик копилота, стор отправляет модели автоотчёт
(`reviewResults`) — та комментирует или действует.

## Модель (lib/trip.ts)

`Trip = { legs, stays }`. **Ночёвки деривативны**: пересчитываются из плеч по
календарным датам в локальном времени. Мутации сбрасывают офферы. `Party`
(взрослые + возрасты детей) влияет на все поиски; маппинг на параметры каждого
MCP-инструмента — `paxArgs()` в lib/search.ts.

## Модули lib (у каждого — свой *.test.ts, всего 715 тестов)

| Модуль | Зачем |
|---|---|
| mcp, cache, search | транспорт к Tutu MCP, TTL-кэш, нормализация офферов |
| trip | модель плана: деривация ночёвок, стыковки, бюджет |
| repair | авторемонт стыковок: перевыбор оффера / мягкий сдвиг даты (кап 2) |
| transfers, hubSuggest | пересадки через хабы: статический список + LLM-подсказка с фолбэком |
| optimize | детерминированный 2-opt перебор городов и дат |
| assist, searchReport | копилот: промпты, инструменты propose_trip/apply_transfer, автоотчёт |
| activityLog | журнал реальных шагов агента + группировка ленты чата |
| geo, tiles, land | Меркатор, XYZ-тайлы, запечённый контур суши, вписывание пинов |
| geoAliases, emptyReasons, windows | «Бали → Денпасар», причины пустой выдачи, неудобные стыки |
| extras, rates | свои траты в валютах, курсы ЦБ со снапшотом |
| aviaFilters, hotelFilters, rooms, hotelCard | фильтры веера, номера, карточка отеля |
| morph, lightMarkdown, thinking, progress | падежи городов, безопасный маркдаун, фразы ожидания LLM, счётчик поиска |
| persist | план в URL-фрагменте + снимок в localStorage (TTL 24 ч) |

## Ключевые решения и почему

- **Session-less MCP.** `tools/call` по streamable HTTP без
  initialize-handshake — проверено живьём, меньше состояния на сервере.
- **Кэш в памяти, не Redis.** Демо живёт в одной реплике; прогрев легенды
  48 с → 0.1 с. Цена — правило «ровно один контейнер» (см. README, деплой).
- **Детерминизм там, где деньги.** Оптимизатор, ремонт, пересадки, checkout —
  чистые перебираемые функции; LLM — черновики, объяснения и выбор из уже
  проверенного (apply_transfer).
- **Своя карта.** d3-геометрии не нужны: Меркатор — страница формул
  (lib/tiles.ts), контур суши запечён скриптом, тайлы MapTiler — слой поверх
  с переключалкой и офлайн-фолбэком. Подписи и толщины домножаются на
  экранный масштаб — зум разводит города, а не увеличивает картинку.
- **Один код-путь для человека и агента.** Черновик копилота, пин отеля на
  карте и кнопка в веере вызывают те же действия стора, что и ручные клики.

## UI-композиция

`page.tsx` — шапка (бюджет, поле статуса агента) + `MapCanvas` (карта:
маршрут, пины отелей, тайлы) + `Timeline` (план, сворачивается в корешок) +
`CopilotCard` (чат с журналом шагов). Модалки: веер вариантов
(VariantsDrawer), номера отеля, пересадка, checkout, оптимизатор, состав,
схема вагона. Стартовый экран — StartScreen: многострочное поле с голосом
и карточки-образцы.
